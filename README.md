## 🤖 AI and software engineering

I treat AI as an engineering tool: useful when it is given clear limits, checked by tests, and kept under the owner's control.

- **AI agents that do real work.** I build agents that file, connect and summarise notes, prepare study material and resurface forgotten ideas, using Claude Code as the engine.
- **Rules before autonomy.** My agents never delete what they were given, never rewrite the owner's own text, mark everything they write, and ask when unsure. Each run is one commit that can be undone.
- **Agent-assisted development.** I use AI coding agents day to day, with specs, small tickets and tests as the guardrails.
- **Tools for agents.** Interest in MCP servers and other ways of giving AI safe access to real systems.

## 🚀 Featured project

### [Folder Git Sync](https://github.com/mohammed-shaker-dev/folder-git-sync)

An Android app that keeps a folder on your phone in step with a GitHub repository. No Git client, no storage permission.

- Two-way sync: phone changes go up as one commit, repository changes come down
- Keeps both versions when a file changed on both sides
- Preview before syncing, scheduled background sync, and a `.gitignore`-style never-sync list
- A sync engine with no dependency on the platform, proven by tests through one seam

## 🧭 How I build

- **Right-size the architecture.** Simple problems get simple solutions.
- **YAGNI.** Don't build what you don't need yet.
- **Tests that matter.** Business logic first, not infrastructure.
- **Clarity over cleverness.** Code is read more than it is written.
